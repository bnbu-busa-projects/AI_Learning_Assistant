Risk 1: Data Leakage

Data leakage happens when sensitive information is copied into an AI tool or sent to an external service without appropriate approval.

  • customer records
  • student grades
  • confidential contracts
  • private operational data

Risk 2: Credential Exposure

API keys and tokens are credentials. If they appear in notebooks, screenshots, chat prompts, or repositories, someone else may be able to use them.

Treat keys like passwords, even when they are used inside code.

Risk 3: Prompt Injection

Untrusted text can contain instructions that try to override the user's intent.

Document content
Model reads content
Unexpected instruction affects answer

Technical Control: Environment Variables

# .env.example MODEL_API_KEY=your_key_here MODEL_BASE_URL=https://example.com/v1 MODEL_NAME=example-model
  • Keep real secrets outside notebooks.
  • Commit only `.env.example`.
  • Load secrets at runtime.
  • Never show real keys in slides or screenshots.

Technical Control: Access Scope

Least privilege

Give a key only the access it needs.

Separate keys

Use different keys for demos, teams, and production.

Rotation

Replace exposed or old keys quickly.

A key that can do everything creates a bigger incident when it leaks.

Local Models as a Mitigation

Running a model locally can reduce external data transfer. It can be useful for demos, experimentation, and sensitive workflows.

Local does not automatically mean safe. It changes the risk profile.

What Local Models Help With

Data residency

Reduce external transfer.

Offline demos

Run without a cloud API.

Experimentation

Try model behavior locally.

Cost control

Reduce usage-based API calls.

What Local Models Do Not Solve

Hallucination

Local models can still be wrong.

Bias

Model behavior still depends on data and design.

Weak devices

Performance may be limited.

Licensing

Terms still matter.

Prompt injection

Untrusted text remains risky.

Bad output

Human review is still required.

Why a Lightweight Dashboard?

  • Shows BI results in a browser.
  • Uses familiar Python code.
  • Supports filters and repeated exploration.
  • Avoids heavy web development.

Common Error: Missing Package

ModuleNotFoundError: No module named 'streamlit'

Fix

pip install -r requirements.txt streamlit run app.py

Common Error: Wrong Data Path

demo_dashboard/ app.py data/ online_retail_transactions_sample.csv
  • Run Streamlit from the demo folder.
  • Use the project `data/` folder.
  • Print the file path when debugging.

Common Error: Blank Chart

Filter

The selected filters may return no rows.

Date parsing

The date column may still be text.

Aggregation

The groupby result may be empty.

Debug the data shape before debugging the chart.
